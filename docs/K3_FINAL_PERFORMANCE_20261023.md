# K3 性能优化与正式复测（2026-10-23）

## 本轮修复了什么

| 问题 | 原因 | 修复位置 |
|---|---|---|
| 本地检索尾延迟超过 100ms | 并发请求同步写审计时相互竞争 | Memory `9d9ff2c`：串行化审计写入，保留同步持久化 |
| 重启后的首次语义检索偏慢 | 加载全部向量时做了不必要的 SQL 排序 | Memory `4d763b4`：取消加载排序，保留完整评分与最终确定性排序 |
| Embedding 偶发 1.5 秒超时、退回关键词检索 | Gateway 每请求重复创建 TLS 上下文，Python GC 阻塞事件循环 | Gateway：每个 Embedding adapter 复用已验证的 TLS 上下文，停止模型时释放；异常或取消时关闭请求客户端 |

没有关闭语义检索、减少语料、修改超时或降低审计持久化要求。Gateway 根因与 A/B/A 对照见 `K3_GATEWAY_TIMEOUT_ATTRIBUTION_20261023.md`。

Gateway 修复提交：`51f501f`（团队 `bianbu/ai/spacemit-ai-gateway`）；Memory 两项源码优化已在团队 main，本次补交归因与最终验收记录。不修改 `debian/changelog`，不打发布 tag。

## 测试环境与口径

- 设备：192.0.2.11；已安装 SDK / memoryd 0.1.30、Runtime 0.1.200、Gateway 0.0.19。
- Memory 使用包含上述修复的候选二进制；Gateway 将候选源码中的方法临时绑定到记忆 Q8 模型实例。测试的不是新发布的 deb 包。
- Runtime、Gateway 和意图模块正常运行，filesearch 保持用户授权的停止状态。没有把 `load1 < 3` 当作产品验收条件。
- 同一份 100000 条隔离语料和 100000 条合成存储向量；查询向量由真实 Gateway Q8 模型生成。合成向量用于规模和扫描性能，不用于召回准确率验收。
- 检索：16 并发，每客户端 200 次，每客户端前 5 次单独统计；每阶段有效样本 3120。
- 语义：8 并发，每客户端 400 次，每次查询不同，避免结果缓存掩盖推理和扫描成本。
- “重启阶段”仅重启隔离 memoryd，不清理操作系统页缓存；模型已经运行，不等于模型冷启动。
- 正式检索门槛为 P95 ≤100ms，语义检索为 P95 ≤2000ms。最大值和首次请求另报，不将 P95 解释为每条请求上限。

## 结果

| 项目 | 测量结果 | 目标 | 结论 |
|---|---:|---:|---|
| 本地查询＋权威读取，热阶段 | P95 77.480ms | ≤100ms | 通过 |
| 本地查询＋权威读取，重启阶段 | P95 87.360ms | ≤100ms | 通过 |
| 语义检索，热阶段，3200 次 | P95 562.542ms | ≤2000ms | 通过；零错误、零超时降级 |
| 语义检索，独立重启阶段，3200 次 | P95 555.709ms | ≤2000ms | 通过；零错误、零超时降级 |
| 本地写入 ACK，1000 次 | P95 59.914ms | ≤100ms | 通过 |
| SDK health 往返，3000 次 | P95 0.338ms | 5ms 参考值 | 在参考值内；不是纯 IPC 开销测量 |

本地检索 P99 为 836.771 / 490.463ms，最大值 1074.636 / 1116.932ms。P95 门槛通过不代表所有尾延迟消失。

检索每阶段另有 80 条预热请求未计入稳态门槛，最大值为 5982.116 / 5576.998ms；这些启动和并发建缓存阶段的等待仍然存在，原始分位数保留在测量摘要中，不能把本轮结论扩展为启动阶段也满足 100ms。

语义首次请求单独测得 1970.951ms（热阶段）、2219.182ms（独立重启阶段）；独立重启首次请求仍超过 2 秒，不能承诺每次首次请求都在 2 秒内。这里依据既定 P95 口径判定通过，未把单次启动开销混入稳态样本或修改指标。热阶段和独立重启阶段 trace 各有 3201 次完成语义计算（含各自首次探测），均无超时降级；稳态语义请求最大值分别为 827.613 / 889.212ms。

写入使用独立新数据库，真实 Embedding 开启，未污染 10 万条语料。复用语料的原检索脚本在跳过建库时默认输出 `write_ack_pass=true`，该默认值不作为写入通过依据。

隔离栈的 Gateway 地址暂时改为不可用的本机端口时，关键词检索仍返回结果；随后恢复完整 Embedding 配置，可继续查询。没有停止共享 Gateway 或模型。

32 并发稳定性补测：两阶段各 1600 次操作、零接口错误。查询＋读取 P95 为 1777.146 / 1884.050ms，仅作超出 16 并发门槛后的负载描述，不宣称 32 并发满足 100ms。

## 正式 Runtime 聊天与环境恢复

同时启用两侧候选优化，通过已安装 Runtime 的 9899 API 执行 4 轮真实模型聊天：`hi`、短会话确认、临时代号追问、开发工具记忆查询。会话为 `codex-formal-final-performance-20261023-f7420ac4`。4 轮均 `run/completed`，before_run / after_run 均完成，没有 `backend_unavailable`；追问正确返回“青竹47”。业务轮实际调用 MCP `memory_retrieve`，对没有相关长期记忆的情况没有虚构工具偏好。

before_run 耗时依次为 419.0 / 150.9 / 136.7 / 160.7ms；after_run 为 367.8 / 18.4 / 19.7 / 20.7ms。这是包含 Hook 启动的耗时，不等于单个 SDK 接口延迟。本次模型由 Runtime 按配置路由，不能据此宣称本地聊天模型推理性能通过；空长期记忆场景也不替代有记忆命中的语义质量测试。

测试后 Memory 已恢复软件源二进制，SHA256 为 `516afdadbbe180ed429f866bc66afdbd66fa436dde2bd98b0d78007e00dcfa99`，并重建 Runtime worker；宿主与 worker 内 socket inode 均为 `828881`。Gateway 候选实例方法已撤销，验证 `restored=true`、无诊断 GC callback。Gateway / 18800 意图模型 / 18802 记忆模型 PID 仍为 1052042 / 1052799 / 1066967，未重启。三个生产服务均 active，Runtime 为 `AGENT_READY`；filesearch 维持原授权停止状态。

## 无效试验与边界

第一次语义重启阶段的尾段与写入补测发生重叠，写入期间还曾暂停测试进程。该阶段及该次写入均保留为原始证据，不作为最终验收依据。写入已独立重跑，语义重启阶段另行独立重跑；不得混用重叠数据宣称相同后台条件。

本报告覆盖本轮已定位的延迟与降级问题，不代表已完成长期稳定性、语义质量、D-Bus 独立延迟或全产品所有非功能项验收。有限负载下零超时不能承诺生产永不超时。
