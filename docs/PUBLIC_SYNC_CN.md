# 公开仓源码同步规则

[English](PUBLIC_SYNC.md) | [简体中文](PUBLIC_SYNC_CN.md)

GitLab 开发仓是功能实现的来源；GitHub 保留独立的公开源码快照历史。不要将内部仓历史强制推送到公开仓。

每次同步时：

1. 记录内部源码提交号、发布 tag 和公开仓的基线提交号。
2. 对比实现改动，将其应用到干净的公开仓工作副本。保留公开仓专用文档和测试适配。目前未提供 GitHub Actions 自动验证。
3. 排除内部 CI 配置、凭据、私密日志、数据库、导出文件、签名私钥和设备现场资料。将内部设备地址及用户主目录路径替换为文档中说明的占位符。
4. 保留可执行文件的权限标记。不要对二进制文件进行全局文本替换。
5. 审核完整差异，并在全新检出的公开源码上执行测试，不能用内部仓测试结果代替。
6. 检查相对链接和中英文文档，再以普通提交发布，并记录其源码基线。

目前公开仓的适配包括设备示例脱敏，以及问候测试中采用最新记录的预期结果。配套的公开插件仓测试 manifest 与 package 的版本是否一致，不依赖内部 Debian 打包文件。这些检查应与发行版软件包版本号保持独立。

行为或共用回归测试的修改，也应向 GitLab 提交。每次后续同步时，都应明确列出公开仓专用适配，避免被覆盖。
